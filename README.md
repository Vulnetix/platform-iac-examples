# Vulnetix Platform IaC examples

A reference for every [Platform IaC](https://docs.vulnetix.com/platform-iac/) kind: one file per
kind that sets **every argument that has a schema default, to that default**, plus the arguments
the kind requires. Copy what you need into your own configuration.

| Directory | What | Use it with |
|---|---|---|
| [`terraform/`](terraform/) | One `<kind>.tf` per kind, and a runnable root module (`versions.tf`, `provider.tf`) | Terraform or OpenTofu 1.11+, provider [`vulnetix/resolve`](https://registry.terraform.io/providers/vulnetix/resolve/latest) |
| [`yaml/`](yaml/) | The same documents as `vulnetix.com/v1` YAML, one `<Kind>.yaml` per kind | `vulnetix config plan` / `apply`, or a GitOps repository |

The files are generated by the provider from the
[config-schemas](https://github.com/Vulnetix/config-schemas) release it is built from, and
checked there: every YAML document validates against its schema, and every Terraform file
applies over an object created from the minimal example, updates it in place, and then plans
clean. `PROVIDER_VERSION` names the provider release they were copied from.

## What a plan shows

- **One-per-tenant kinds** (`organization`, `quality_gate`, `package_firewall_policy`,
  `ai_firewall_policy`, `notification_defaults`, `remediation_policy`, `scanner_profile`,
  `ssvc_policy`, `factory_settings`, `aws_connection`, `wiz_connection`): on a tenant that left
  these settings at their defaults, the only values a plan sets are ones that are unset. Where
  your tenant holds a different value, applying would put the default back. To see that as a diff
  rather than overwrite it, import the object first:

  ```hcl
  import {
    to = vulnetix_quality_gate.default
    id = "default"
  }
  ```

- **Every other kind** declares an example object (named as in the minimal example, such as
  `quarterly-owasp`). A plan shows it as created; applying would create it. Change the name and
  the values before applying, or import an existing object by its name instead.

Secrets are never in these files: a secret is a write-only `*_wo` argument with no default, so
the reference leaves it out. See each kind's `advanced.tf` in the provider's
[examples](https://github.com/Vulnetix/terraform-provider-resolve/tree/main/examples/resources)
for every argument, secrets included.

## Run it

```sh
export VULNETIX_ORG_ID=...    # your organisation UUID
export VULNETIX_API_KEY=...   # the ApiKey of a developer service account
just check                    # fmt and validate; needs no credentials
just plan                     # terraform plan against your tenant (reads only)
```

Without `just`: `terraform -chdir=terraform init && terraform -chdir=terraform plan`.

## Update

`just sync v1.4.2` copies the reference files from a provider release tag. Run it after a
provider release that changes a kind, then `just check`.
